P3 + P4

A stack is an array and one integer

Push and pop it yourself. Watch what Top does.

Push: move Top up one, then store.  Pop: read, then move Top down one.
That is the entire data structure. Nothing is ever moved — only the integer changes.
P3 + P4

Why −1, and not 0?

Last lesson a null pointer was 0x0000…0. This lesson empty is −1. Both are right, and the reason they differ is the whole idea.

a real machineCambridge's array
A pointer holds an address.A "pointer" holds an array index.
Address 0 is legal to write down, but the OS deliberately leaves it unmapped — nothing can ever live there. Index 0 is an ordinary element. Contents[0] is the first item.
So 0 is free to mean "nothing". It was made impossible, by decree. So 0 cannot mean "nothing" — it already means something.
null = 0null = −1
A sentinel has to come from outside the set of legal values. Not from the edge of it — from outside it. Real memory has no such value, so the operating system manufactures one. An array index cannot, so you go below the range: −1 is the largest impossible index.
🕳 and when the sentinel is a lie ↓

🕳 When the sentinel is a lie

Here are two sentences from a real Paper 4 question. Read them together.

"A linked list stores positive integer data in a 2D array…
A linked list node with no data is initialised with the integer −1." — Nov 2024 Paper 41 Q3, © UCLES
−1 is safe as "empty" only because of the first sentence. The question has quietly promised the data will never be negative. Change it to temperatures, or bank balances, or scores that can drop below zero — and the sentinel collides with real data. There is then no way on earth for the program to tell an empty node from a cold Tuesday.
The professional name is in-band signalling — using a value from inside the data's own range to mean something that is not data. It works in an exam and would be rejected in a code review.
And you will see both designs in one question, one line apart — hold that thought until slide 9.

The habit worth taking away is not "−1 is wrong".
It is reading for the promise the sentence above just made.

P3 + P4

The two questions that are actually marked

OVERFLOW
Push onto a full stack.
Top is already at the last index and there is nowhere to put it.

UNDERFLOW
Pop an empty stack.
Top is −1 and there is nothing to return.

These are not edge cases. They are the question. A stack that works when it is neither full nor empty is worth almost no marks — the middle of the array is the easy part and every candidate gets it.
🧾 OUTSIDE THE EXAM HALL
Overflowing a real stack is called a stack overflow, and for thirty years it was the most exploited security bug in computing: write past the end of a buffer, land on the return address, and the machine jumps wherever you told it to. The check you are writing on this slide is the fix. Whole languages were designed because people kept forgetting it.
It is so famous that the largest programming question-and-answer site on earth is named after it — stackoverflow.com, where a generation of programmers went to ask why their program had died. And there is a decent chance the answers on it helped train the AI you use to write code, which makes the name quietly perfect: a website about crashing, teaching the machines.

A queue is an array and two integers

Cambridge's own names: HeadPointer comes off the front, TailPointer goes on the back. Both start at −1.

Enqueue at the tail, dequeue from the head — first in, first out. The printer queue, the OS process queue, the keyboard buffer holding the letters you typed while the machine was busy.
P3 + P4

Enqueue and Dequeue — the marked signatures

This is the shape Cambridge marks. Learn the return values, not just the idea.

📐 the safe design and the dangerous one ↓

📐 One question. Both designs. One line apart.

Look again at what the two functions hand back.

Enqueue → a separate BOOLEAN

The answer to "did it work?" travels in its own channel. It cannot be confused with data, because it is not the same kind of thing as data.

This is the safe design. It stays safe no matter what the queue holds.
Dequeue → −1

The answer to "did it work?" is smuggled inside the value itself. A caller who gets −1 cannot tell "the queue was empty" from "the queue held −1".

In-band signalling — and it survives here only because the question promised the data would be positive.
Write both exactly as marked — this is the convention the exam uses and the marks follow it. Then notice, out loud, that one of them is better engineering than the other, and that you can now say which and why. That sentence is worth more than the six marks.
P3 + P4

Now break it

Press walk it. Three in, three out, two in. Then try to add one more.

The queue walks up the array and never comes back. TailPointer has hit the end, so it reports full — while three slots sit empty behind HeadPointer, unreachable. A linear queue can be full and nearly empty at the same time.
P3 + P4

The fix is one operator

The array does not have to end. Bend it into a ring: when a pointer runs off the last index, send it back to 0.

TailPointer ← (TailPointer + 1) MOD MaxSize
That single MOD reclaims every slot the linear queue abandoned. Index 4 wraps to 0, and the space behind HeadPointer comes back into use.
And it costs you something. Once the array is a ring you can no longer tell full from empty by comparing the pointers — in both cases they meet. So a circular queue must also count its items, or deliberately waste one slot.
🧾 HOW OFTEN THIS IS ASKED — AND IT IS NOT A HOLE
Circular queues appear in 4 of the 24 papers in the archive, and only on Paper 4. That is rarer than the linear queue and it is still examinable, which is exactly why this is a slide and not an optional dig. Know the MOD line, and know the counting problem it creates. That is the whole of it — but know it.

What you can build now

A stack — an array and one integer.
A queue — an array and two integers.
Both with overflow and underflow handled, which is where the marks were all along.
And one idea that outlives both: a sentinel must come from outside the range of legal values — which is why empty is −1 and not 0.
And notice how little separates them. Both are an array and some indices. A stack takes items off the end it puts them on; a queue takes them off the other end. That is the entire difference — change which index you read from and the structure becomes the other one. A data structure is never really a thing. It is a rule about which end you are allowed to touch.
But look at what you had to decide before the program ran. Five elements. Fifty. Two hundred. Every structure on this slide has a size chosen in advance — and when it is full it is full, even when, as you saw, it is nearly empty.
