A guard is not a memory measurement

Python exposes a recursion guard through sys.getrecursionlimit(). It can stop a program before resources are exhausted.

A runtime also needs resources for execution state. The implementation and build decide their layout and costs.

P3

What must survive while a call waits?

One call's worth of paperwork is called a stack frame. Three things go in it, and the exam names two of them.

def RecursiveVowels(Value): if len(Value) == 0: return 0 First = Value[0] if First in "aeiou": return 1 + RecursiveVowels(Value[1:]) # line 6 return RecursiveVowels(Value[1:]) # line 7

The code exists once. A thousand calls share these seven lines — so whatever is per-call cannot be the code.

① the return address — which line do I come back to? Call from line 6 and the answer must return to line 6, where a 1 + is still waiting for it.
② the local variables — this call's own Value and First. Seven calls are alive at once and every one has a different First.
③ the parameters, which are just locals that arrived from outside.

For the compiler question, explain saved return addresses and local values, then winding and unwinding. A frame is the teaching name for per-call state. Python preserves local bindings; mutable referenced objects can still be shared between calls.

P3

📐 You have already seen both halves — in colour

Winding 递推 — calls going down. Each one pushes a frame and stops halfway through, holding an unfinished sum. In last lesson's trace table these were the green rows.
Unwinding 回溯 — returns coming back up, once the base case has been reached. Each one pops a frame and hands a value to the line that was waiting. The amber rows, with the call number in brackets.
So the two colours on that table were never a teaching device. They are push and pop — and the reason the trace table is marked in two halves is that the machine does two different things in them.

Transfers: every debugger you will ever open shows you this stack, newest frame first, and reading it is how professionals find bugs.
Does not: the phrase "winding" is Cambridge's. Elsewhere it is just "the stack growing".
P3

Why a stack, and not a queue?

Do not take it on trust. Step this one — it is the same recursion, served oldest first.

The order is forced, not chosen. The call made last is the one that finishes first — it is innermost, and everyone outside is waiting on it. That is what LIFO means, and recursion produces it whether you like it or not.   Nov 2021 P31 Q10(b) [3]: LIFO · pushed each call · popped as the function ends · enables unwinding to maintain the required order.
🧹 You already obey this every day. You are vacuuming; you notice a spill and stop to wipe it. You cannot finish the vacuuming until the wiping is done — the job that interrupted comes off the pile first. Serve the oldest job first and you would be told to finish vacuuming while still holding the cloth. An interrupted job can only finish after the job that interrupted it.
🕳 every call uses it — recursion just makes it visible ↓

🕳 Recursion is not special. It is ordinary, in bulk.

"Give two other uses of a stack." [2] — June 2022 Paper 31 Q5(c), after a question about evaluating an expression  © UCLES
The published answer: recursion · procedure calls · interrupt handling (storing the contents of registers) · implementing ADTs.
The exam model uses a stack for procedure calls: unfinished calls preserve their return position and local state. Real runtimes can optimise or represent calls differently. Recursion makes the repeated state visible; the published answer also accepts interrupt handling and ADT implementations.
Interrupt handling. When a key is pressed mid-program, the CPU must remember exactly where it was and what was in its registers — push, handle, pop, resume. Same structure, different owner.
And that expression-evaluating question the bullet came from? Push the numbers, pop two on each operator. The same two operations, a third time.

P3

So when is it worth it?

This is a marked question too — June 2025 Paper 32 Q11(b) [2] and a recent sitting, Paper 33 Q11 [3]. The published answers, near enough word for word:

When the problem naturally breaks into a smaller version of itself. Then the code is the definition, and there is nothing to get wrong between them.
When there are many branches, or the iterative version would be too complex — a tree has two directions to go at every node, and a loop has to keep its own list of where it has not been.
The examples the scheme prints: factorial · a mathematical series · Fibonacci · compound interest · tree traversal · evaluating an RPN expression.
And the honest other half. Counting the vowels in a string is not one of these — it is a walk from one end to the other, which is what a loop is for. The exam asked for it recursively to see whether you can, not because it is the right tool.
🧾 OUTSIDE THE EXAM HALL — what professionals actually do
A lot of production recursion does get rewritten as a loop, often with an explicit stack, exactly as on the next slide. But the rule is not "recursion is for exams". Depth decides.
Left recursive: tree and graph work, parsers, divide-and-conquer — a balanced tree of a million nodes is about 20 frames deep, and the recursive version is the one you can read.
Rewritten as a loop: anything whose depth grows with the size of the input — a list walk, a string walk, a degenerate tree. That is where a real user's data becomes a crash.
And the trap: most languages do not remove the frame even when the call is the last thing you do. Python refuses to on purpose. So you cannot assume the compiler will save you.

P4

🕳 Look at what the paper's own loop does

FOR X ← 0 TO LengthString - 1 FirstCharacter ← MID(Value, 0, 1) IF FirstCharacter = 'a' OR … THEN Total ← Total + 1 ENDIF Value ← MID(Value, 1, LENGTH(Value)-1) NEXT X

Nov 2023 Paper 41 Q1, part (a) — as printed. © UCLES

Look at the last line of the body. It chops the first character off and goes round again with the rest of the string. That is first + rest — the recursive decomposition — with a counter bolted on the side to stop it.
So the rewrite is nearly mechanical: delete the counter, return 0 when the string is empty, and let the call take the rest. Look for that pattern first in any "rewrite it recursively" question — when a loop shortens its own data each pass, the recursion is already written.
