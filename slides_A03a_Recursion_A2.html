So what is the difference?

Both call themselves. One finished and got marked; one has been running since your grandmother told it.

# the monk def tell_story(): print("从前有座山……") tell_story() # always
# the homework def InOrder(Node): if ArrayNodes[Node][0] != -1: # SOMETIMES InOrder(...)
The monk's story calls itself every time, unconditionally. Yours calls itself only when there is a child to visit — and a tree runs out of children. There is a case where the calling stops.
That case has a name, and the name is worth three marks on Paper 3: the base case.
"State three essential features of recursion" [3] — Nov 2021 Paper 31. The published answer, in its own words: ① a base case / stopping condition  ·  ② a general case  ·  ③ … which calls itself (defined in terms of itself)  ·  ④ … which changes its state and moves towards the base case.

P3

📐 Having a base case is not the same as reaching it

def countdown(n): if n == 0: # base case ✓ return 0 return countdown(n - 1)

countdown(5) → 5, 4, 3, 2, 1, 0. Stops.

def countup(n): if n == 0: # base case ✓ (identical!) return 0 return countup(n + 1)

countup(5) → 6, 7, 8, 9 … never.

📐 SAME BASE CASE, OPPOSITE FATES
Both functions have a base case, and it is the same base case. One walks toward it; the other walks away and the condition is never true again. That is why the published mark point is not "has a base case" but "changes its state and moves towards the base case" — four extra words, one whole mark, and the difference between a program and a crash.
Python observation: an unbounded countup(5) reaches the configured recursion guard and raises RecursionError. A base case must be reached from the supplied input. The next lesson separates the exam stack model from runtime resource limits.

🕳 That table is a polite lie

The published table has 10 rows. Run Fib(5) honestly and the machine makes 15 calls — the widget counted them. Cambridge's table walks one path down and back up, and quietly reuses answers it never shows being computed.
Nothing is remembered between branches. Fib(2) is worked out three separate times from scratch; Fib(1) five times. Each branch re-derives what the branch beside it already knew.
to compute calls made

Ten more terms costs a hundred times the work. The 40th Fibonacci number is a 10-digit answer that a laptop can compute instantly — and this way of computing it takes a third of a billion calls.

The fix is one line and it has a name: memoisation — write each answer down the first time, look it up ever after. Fib(30) falls from 2.7 million calls to 31 pieces of real work. Recursion was never the problem; forgetting was.
P3 + P4

Now the structure you built — searched recursively

Named fields first, because the shape is the lesson. The exam's columns are on the right, and they are the same thing.

def search(node, target): if node is None: # base case ①: not there return None if node.data == target: # base case ②: found it return node if target < node.data: return search(node.left, target) return search(node.right, target)
Two base cases and two general cases — the features in the plural. And notice: every branch says return search(…), never just search(…). The answer has to be handed back up.
# the exam's form — same walk, columns for names def SearchValue(Root, ValueToFind): if Root == -1: return -1 if ArrayNodes[Root][1] == ValueToFind: return Root if ArrayNodes[Root][1] > ValueToFind: return SearchValue(ArrayNodes[Root][0], ValueToFind) return SearchValue(ArrayNodes[Root][2], ValueToFind)

📐 The same tree, two different signatures

# Nov 2021 P41 — takes the INDEX def InOrder(Node): if ArrayNodes[Node][0] != -1: InOrder(ArrayNodes[Node][0]) print(ArrayNodes[Node][1])

Called as InOrder(RootPointer).

# Nov 2022 P41 — takes the ROW ITSELF def PostOrder(RootNode): if RootNode[0] != -1: PostOrder(ArrayNodes[RootNode[0]]) ... print(RootNode[1])

Called as PostOrder(ArrayNodes[RootPointer]).

📐 ONE YEAR APART, SAME TREE, SAME BOARD
One passes a number; the other passes a row. Both are published; the Nov 2022 mark point accepts either — "one parameter (root node or index of root node)". A candidate who memorised a signature meets the other one and freezes. Learn the shape: go left if there is a left, deal with me, go right if there is a right. The parameter is a detail you read off the question.
Traversal order is just where the print sits among the two calls. Left · me · right = in-order → sorted. Left · right · me = post-order. Me · left · right = pre-order. Three orders, one shape, one line moved.

🕳 The oldest algorithm still running — and it is recursive

def gcd(a, b): if b == 0: return a return gcd(b, a % b)
Euclid, Elements Book 7, around 300 BCE. Written as geometry — keep taking the smaller from the larger — about 2 300 years before anything existed to run it on. Recursion as a way of thinking is older than the machine by two millennia.
gcd(48, 18) → gcd(18, 12) # 48 mod 18 → gcd(12, 6) # 18 mod 12 → gcd( 6, 0) # 12 mod 6 → 6 # base case
Four frames. Fib(5) needed fifteen calls for a smaller answer. The difference is how fast the argument shrinks: −1 each time is slow, MOD is brutal — and depth falls from n to about log n.

Press gcd(48, 18) on the tracer two slides back and watch a stack that barely gets off the ground.

When is recursion worth it?

the jobuse recursion?
walk a tree · search it, print it in orderyes — the structure is defined in terms of itself, so the code that walks it should be too. A loop needs you to build a stack by hand.
divide and conquer · binary search, merge sortyes — "solve half, then the other half" is a recursive sentence.
count to ten · total an array · anything linearno — a loop is shorter, faster, and cannot run out of stack. Recursion here is showing off.
Fibonacci, naivelyno — you saw the number. 331 million calls for a 10-digit answer.
The rule of thumb worth writing down: reach for recursion when the data itself branches — a tree, a folder inside a folder, a problem that splits in two. Reach for a loop when the data is a straight line.
Count two different things. Fib(5) makes 15 calls in total, with at most 5 Fibonacci calls active together. The branches run in turn. Each unfinished call retains its own state; completed calls no longer occupy an active frame.
